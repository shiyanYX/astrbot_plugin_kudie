# ADR-0001: 内置爬虫 + 双 LLM 搜索链路

**日期:** 2026-06-04
**状态:** 已采纳

## 背景

插件 v2.0 完全依赖 LLM 训练数据生成文章，对"小众游戏"和"当前热点舆论"信息不足。需要引入外部信息获取能力。

## 决策

### 1. 内置爬虫而非第三方搜索 API

**理由：** 贴吧、B站、ACG wiki 没有统一的公开搜索 API。百度站内搜索是覆盖面最广的入口，可作为默认策略，同时保留各自站内搜索作为可切换选项。

**替代方案：** 使用 Bing Search API / SearXNG 等通用搜索引擎。放弃原因：(a) 需要额外服务依赖 (b) API 额度成本 (c) 对贴吧/B站内容覆盖不一定更好。

### 2. 双 LLM 调用链路

搜索结果噪声大（包含标题、正文片段、评论），直接注入 prompt 会导致文章质量下降。采用两步处理：

1. **第一次 LLM 调用：** 将搜索结果加工为"事件背景 + 角色背景"摘要
2. **第二次 LLM 调用：** 基于摘要撰写文章

**代价：** 多一次 LLM 调用，耗时增加。**收益：** 文章质量显著更好。

### 3. 搜索默认关闭

搜索链路比纯 LLM 慢（爬虫 + 额外 LLM 调用），不适用于所有场景。默认 `/尽孝` 使用缓存数据 + LLM 常识，用户用 `/尽孝搜索` 显式触发实时搜索。Cookie 通过 `/尽孝登录` 命令写入配置。

### 4. 角色数据长期缓存（7 天 TTL）

角色信息（性别、年龄、类型）变化极慢，7 天缓存避免对 wiki 的重复请求。事件搜索结果短期缓存（10 分钟），避免同一话题重复搜索。

### 5. 固定三段式 Prompt

第二次 LLM 调用的 prompt 结构固定为：`【角色背景】+【事件背景】+【任务】`。清晰、可预测、便于调试。不引入用户可配置的模板——过于灵活反而不利于质量稳定。

### 6. 贴吧 Cookie 认证

贴吧不登录无法获取完整评论。用户通过 `/尽孝登录` 命令提供 Cookie，爬虫带 Cookie 请求。Cookie 为空时仅抓取公开可见内容并标注信息不完整。

## 影响

- `core/article_generator.py` — 需重构为双 LLM 调用链路
- `core/prompt_builder.py` — 新增背景摘要 prompt 模板
- 新增 `core/search/` 模块 — 爬虫、缓存、搜索词优化
- 新增 `core/character_cache.py` — 角色信息缓存
- `_conf_schema.json` — 新增搜索相关配置项
- `main.py` — 新增 `/尽孝搜索`、`/尽孝登录` 命令
